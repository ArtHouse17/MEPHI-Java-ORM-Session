# Hibernate Academy

Учебный REST API для курса «ORM и Hibernate». Преподаватель составляет программу и расписание, добавляет задания и тесты. Студент записывается на курс, сдаёт работы и смотрит свои результаты.

Java 21, Maven, Spring Boot, Spring Data JPA, Hibernate, PostgreSQL 16 и Liquibase.

## Запуск

Скопируй `.env.example` в `.env`, заполни `DB_PASSWORD` и выполни команду из корня проекта.

```sh
docker compose up --build -d
```

После старта открой [список курсов](http://localhost:8080/api/courses). Логи приложения можно посмотреть через `docker compose logs -f app`. Команда `docker compose down` останавливает контейнеры, данные остаются в отдельном томе.

Без Docker понадобятся JDK 21, Maven и PostgreSQL. Создай базу и задай `DB_URL` (например, `jdbc:postgresql://localhost:5432/academy`), `DB_USER` и `DB_PASSWORD`. Запусти `mvn spring-boot:run`. При первой сборке Maven скачает зависимости. При запуске Liquibase создаст таблицы, а Hibernate проверит маппинг.

Чтобы заполнить базу примерами, задай `SPRING_PROFILES_ACTIVE=dev`. Compose запускает приложение с этим профилем.

## Как проверить API

Открой [demo.http](demo.http) в IntelliJ IDEA и выполни запросы сверху вниз. Сначала получишь программу и расписание демо-курса. Дальше отправишь работу от лица студента, выставишь оценку от лица преподавателя и пройдёшь тест.

В чистой демобазе `student@example.test` уже записан на курс и может сдать работу и тест. У `reviewer@example.test` уже есть оценка и результат теста.

Передавай ID студента или преподавателя в `X-Actor-Id`. Сервисы проверяют по нему роль, запись на курс и авторство. В учебной версии клиент задаёт этот ID напрямую, без входа по логину и паролю.

## REST API

У всех маршрутов префикс `/api`. Для CRUD используй `GET` и `POST` на адресе коллекции, а для чтения, изменения или удаления одной записи добавь её ID к пути и вызови `GET`, `PUT` или `DELETE`. ID родителя в строке запроса нужен для списка и создания.

| Ресурс | Методы | Поля JSON при записи |
| --- | --- | --- |
| `/users` | CRUD | `name`, `email`, при создании `role` со значением `STUDENT`, `TEACHER` или `ADMIN` |
| `/users/{id}/profile` | GET, PUT | `bio`, `avatarUrl`, оба поля необязательны |
| `/categories` | CRUD | `name` |
| `/tags` | CRUD | `name` |
| `/courses` | CRUD, фильтр списка `?tagId=` | `title`, `description`, `categoryId`, `teacherId`, `startDate`, `durationWeeks` |
| `/courses/{id}/tags` | GET, PUT | `{"tagIds":[1,2]}`, пустой массив удаляет связи |
| `/courses/{id}/curriculum` | GET | Программа курса с модулями и уроками |
| `/courses/{id}/schedule` | GET | Все занятия курса в порядке начала |
| `/modules?courseId=` | CRUD | `title`, `description`, `position` |
| `/lessons?moduleId=` | CRUD | `title`, `content`, `position` |
| `/lesson-resources?lessonId=` | CRUD | `title`, `url` |
| `/lesson-sessions?lessonId=` | CRUD | `startsAt`, `endsAt`, `location` |

| Маршрут | Методы и правила |
| --- | --- |
| `/courses/{courseId}/enrollments` | GET списка студентов, POST с `{"studentId":2}` |
| `/courses/{courseId}/enrollments/{studentId}` | GET записи, DELETE для отмены записи |
| `/users/{studentId}/enrollments` | GET списка курсов студента |
| `/courses/{courseId}/reviews` | GET отзывов, POST с `{"rating":5,"comment":"Хорошие примеры"}` и ID записанного студента |
| `/courses/{courseId}/reviews/{reviewId}` | GET, PUT и DELETE, изменение и удаление доступны автору |
| `/assignments?lessonId=` | CRUD с полями `title`, `description`, `dueAt`, `maxScore`. Изменения выполняет преподаватель курса |
| `/assignments/{id}/submissions` | POST с `{"content":"Текст решения"}` от студента, GET списка преподавателем |
| `/assignments/{id}/submissions/{submissionId}` | GET преподавателем курса или автором решения |
| `/assignments/{id}/submissions/{submissionId}/grade` | PUT преподавателем с `{"score":95,"feedback":"Разберите запросы"}` |
| `/quizzes?moduleId=` | CRUD с полем `title`. GET элемента возвращает тест с вариантами без ключа. Изменения выполняет преподаватель |
| `/questions?quizId=` | CRUD с полями `text`, `points`, `position`. Изменения выполняет преподаватель |
| `/answer-options?questionId=` | CRUD преподавателем с полями `text`, `correct`, `position` |
| `/quizzes/{id}/attempts` | POST от студента с `{"answers":[{"questionId":1,"optionId":1}]}`, GET списка преподавателем |
| `/quizzes/{id}/attempts/{attemptId}` | GET преподавателем или автором попытки |
| `/quizzes/{id}/result` | GET попытки студента, указанного в `X-Actor-Id` |

Передавай `startDate` в формате `YYYY-MM-DD`. Для даты со временем используй ISO 8601 с часовым поясом, например `2030-01-10T10:00:00Z`. Позиции начинаются с 1. Две записи с одним родителем не могут занимать одну позицию.

При создании API отвечает `201 Created` и указывает адрес новой записи в `Location`. При удалении возвращает `204 No Content`. Ошибки приходят в формате `application/problem+json`. Проверь поля запроса при `400` и права участника при `403`. Код `404` означает, что запись не найдена, а `409` возвращается, например, если студент уже сдавал это задание. Для ошибок валидации тела смотри сообщения по полям в `fields`.

## Структура проекта

| Пакет | Что в нём |
| --- | --- |
| `accounts` | Пользователи, роли и профили |
| `catalog` | Курсы, модули, уроки, материалы, расписание, теги, запись на курс и отзывы |
| `assignments` | Задания, решения и оценки |
| `quizzes` | Тесты, варианты ответов и результаты |
| `common` | Общая обработка ошибок и вспомогательные настройки |

Контроллер принимает HTTP-запрос и возвращает DTO. Сервис проверяет правила и выполняет операцию в транзакции. Например, `SubmissionService` перед сохранением через репозиторий проверяет, что студент записан на курс, срок сдачи не прошёл и работы от этого студента ещё нет.

По умолчанию сервисы открывают транзакции с `readOnly = true`. Методы, которые меняют данные, открывают транзакции записи. Блокировки при сдаче работы или теста берутся в этих же транзакциях.

В модели 18 JPA-сущностей. У каждого аккаунта свой профиль (1:1). В одном курсе может быть несколько модулей (1:N). Курсы связаны с тегами через таблицу `course_tag` (M:N). Запись студента на курс тоже M:N. У неё есть отдельная сущность `Enrollment`, которая хранит дату записи.

Ограничения уникальности в базе запрещают повторные записи и попытки. Когда студент отписывается от курса, его работы и результаты сохраняются.

В модуле может быть один тест. Сдать его можно, если у каждого вопроса ровно один правильный вариант из двух или более. После первой попытки состав теста фиксируется, чтобы сохранённые ответы и баллы соответствовали вопросам.

### Ленивая загрузка

Open Session in View выключен. Интеграционный тест показывает `LazyInitializationException` при чтении модулей после закрытия сессии. Для программы курса `@EntityGraph` загружает модули, а репозиторий получает уроки для всех модулей одним запросом.

## Тесты

```sh
mvn -Pquality clean verify
```

- `QuizScorerTest` проверяет подсчёт баллов и неверные варианты ответов.
- `PlatformApiTest` проверяет CRUD, правила записи и сдачи, ограничения базы и ленивую загрузку.
- `DemoDataTest` проверяет заполнение базы демоданными.

Тесты по умолчанию идут на H2 с профилем `test`. Для запуска на PostgreSQL создай отдельную тестовую базу и задай `ACADEMY_TEST_DB_URL`, `ACADEMY_TEST_DB_USER` и `ACADEMY_TEST_DB_PASSWORD`. В GitHub Actions настроены оба прогона и проверка ответа API после старта через Compose.
