# MEPHI

Учебный REST API для курса «ORM и Hibernate». Преподаватель составляет программу и расписание, добавляет задания и тесты. Студент записывается на курс, сдаёт работы и смотрит результаты.

Java 21, Maven, Spring Boot, Spring Data JPA, Hibernate, PostgreSQL 16 и Liquibase.

## Запуск

Скопируй `.env.example` в `.env`, заполни `DB_PASSWORD` и запусти Docker Compose из корня проекта.

```sh
docker compose up --build -d
```

После запуска открой [список курсов](http://localhost:8080/api/courses). Посмотреть логи можно через `docker compose logs -f app`. Команда `docker compose down` остановит контейнеры, данные останутся в томе PostgreSQL.

Для запуска без Docker нужны JDK 21, Maven и PostgreSQL. Создай базу и задай `DB_URL` (например, `jdbc:postgresql://localhost:5432/academy`), `DB_USER` и `DB_PASSWORD`. Затем выполни `mvn spring-boot:run`. Liquibase создаст таблицы, а Hibernate проверит маппинг.

Для демонстрационных данных задай `SPRING_PROFILES_ACTIVE=dev`. В Docker Compose этот профиль уже включён.

## Как проверить API

Открой [demo.http](demo.http) в IntelliJ IDEA и выполни запросы сверху вниз. Можно посмотреть программу и расписание, сдать и оценить работу, пройти тест и узнать результат.

Сценарий рассчитан на свежую демобазу. Студент `student@example.test` уже записан на курс и может сдать задание и тест. У `reviewer@example.test` уже есть оценка и результат теста.

В запросах от имени студента или преподавателя передавай его ID в заголовке `X-Actor-Id`. По нему проверяются роль, запись на курс и авторство. В учебной версии вход по логину и паролю не нужен.

## Маршруты API

Все пути начинаются с `/api`. Для списка и создания используй `GET` и `POST` по адресу коллекции. Для чтения, изменения и удаления отдельной записи добавь её ID к пути и используй `GET`, `PUT` или `DELETE`. Если в примере указан параметр вроде `?courseId=`, передай его для списка или создания.

### Пользователи и курсы

- `/users` — имя (`name`) и почта (`email`). При создании задай `role` со значением `STUDENT`, `TEACHER` или `ADMIN`.
- `/users/{id}/profile` — `GET` и `PUT` для профиля. Поля `bio` и `avatarUrl` необязательны.
- `/categories` и `/tags` — категории и теги. Для записи нужно поле `name`.
- `/courses` — курсы с полями `title`, `description`, `categoryId`, `teacherId`, `startDate` и `durationWeeks`. Список можно отфильтровать через `?tagId=`.
- `/courses/{id}/tags` — `GET` для чтения, `PUT` для замены тегов. Пример тела `{"tagIds":[1,2]}`. Пустой массив удалит связи.
- `/courses/{id}/curriculum` — программа с модулями и уроками. `/courses/{id}/schedule` — занятия по времени начала. Оба маршрута используют `GET`.

### Содержание курса

- `/modules?courseId=` — модули (`title`, `description`, `position`).
- `/lessons?moduleId=` — уроки (`title`, `content`, `position`).
- `/lesson-resources?lessonId=` — материалы (`title`, `url`).
- `/lesson-sessions?lessonId=` — занятия (`startsAt`, `endsAt`, `location`).

### Запись на курс и отзывы

- `/courses/{courseId}/enrollments` — `GET` для списка студентов, `POST` для записи на курс. Пример тела `{"studentId":2}`.
- `/courses/{courseId}/enrollments/{studentId}` — `GET` для чтения, `DELETE` для отмены записи. `/users/{studentId}/enrollments` — `GET` для списка курсов студента.
- `/courses/{courseId}/reviews` — `GET` для списка, `POST` для добавления отзыва от записанного студента. Пример тела `{"rating":5,"comment":"Хорошие примеры"}`.
- `/courses/{courseId}/reviews/{reviewId}` — `GET`, `PUT` и `DELETE`. Изменять и удалять отзыв может его автор.

### Задания и тесты курса

- `/assignments?lessonId=` — задания (`title`, `description`, `dueAt`, `maxScore`). Их изменяет преподаватель курса.
- `/assignments/{id}/submissions` — преподаватель получает список работ через `GET`, студент сдаёт решение через `POST`. Пример тела `{"content":"Текст решения"}`.
- `/assignments/{id}/submissions/{submissionId}` — `GET` для преподавателя курса или автора решения.
- `/assignments/{id}/submissions/{submissionId}/grade` — преподаватель выставляет оценку через `PUT`. Пример тела `{"score":95,"feedback":"Разберите запросы"}`.
- `/quizzes?moduleId=` — тесты (`title`). `GET /quizzes/{id}` возвращает вопросы и варианты без ключа.
- `/questions?quizId=` — вопросы (`text`, `points`, `position`). `/answer-options?questionId=` — варианты (`text`, `correct`, `position`). Тест, вопросы и варианты редактирует преподаватель курса.
- `/quizzes/{id}/attempts` — `GET` для списка попыток у преподавателя, `POST` для сдачи теста студентом. Пример тела `{"answers":[{"questionId":1,"optionId":1}]}`.
- `/quizzes/{id}/attempts/{attemptId}` — `GET` для преподавателя курса или автора попытки. `/quizzes/{id}/result` — `GET` для результата студента, указанного в `X-Actor-Id`.

Дата начала курса (`startDate`) передаётся в формате `YYYY-MM-DD`. Для даты со временем используй ISO 8601 с часовым поясом, например `2030-01-10T10:00:00Z`. Позиции начинаются с 1 и не повторяются внутри одного родителя.

API возвращает `201` и адрес новой записи в `Location` при создании, а при удалении — `204`. Ошибки приходят в формате `application/problem+json`. При неверных данных возвращается `400`, при отсутствии прав — `403`, если запись не найдена — `404`. Например, вторая попытка сдать одно задание вернёт `409`. Ошибки валидации отдельных полей можно посмотреть в `fields`.

## Как устроен проект

- `accounts` — пользователи, роли и профили.
- `catalog` — курсы, модули, уроки, материалы, расписание, теги, записи и отзывы.
- `assignments` — задания, решения и оценки.
- `quizzes` — тесты, варианты ответов и результаты.
- `common` — общая обработка ошибок и настройки.

Контроллеры принимают HTTP-запросы и возвращают DTO. Сервисы проверяют правила, репозитории работают с базой. Например, `SubmissionService` проверяет запись на курс, срок и наличие предыдущей работы перед сохранением решения.

Для чтения сервисы по умолчанию используют транзакции с `readOnly = true`. Изменения идут в транзакциях записи. При сдаче задания или теста блокировки берутся в той же транзакции, что и сохранение результата.

В проекте 18 JPA-сущностей. У пользователя один профиль (1:1), у курса несколько модулей (1:N). Курсы и теги связаны через таблицу `course_tag` (M:N). Студенты и курсы тоже связаны как многие ко многим. Дата записи хранится в `Enrollment`.

В модуле может быть один тест. Сдать его можно, если в каждом вопросе есть хотя бы два варианта и ровно один правильный. После первой попытки тест нельзя редактировать. Ограничения базы защищают от повторной записи, сдачи задания и прохождения теста. Если студент отписывается от курса, его работы и результаты сохраняются.

Open Session in View выключен. Тест показывает, что чтение ленивой коллекции после закрытия сессии вызывает `LazyInitializationException`. Для загрузки программы курса `@EntityGraph` получает модули, а репозиторий загружает уроки всех модулей одним запросом.

## Тесты проекта

```sh
mvn -Pquality clean verify
```

- `QuizScorerTest` проверяет подсчёт баллов и обработку неверных ответов.
- `PlatformApiTest` проверяет работу API, правила записи и сдачи, ограничения базы и ленивую загрузку.
- `DemoDataTest` проверяет загрузку демонстрационных данных.

По умолчанию тесты используют H2 и профиль `test`. Для прогона на PostgreSQL создай отдельную тестовую базу и задай `ACADEMY_TEST_DB_URL`, `ACADEMY_TEST_DB_USER` и `ACADEMY_TEST_DB_PASSWORD`. В GitHub Actions есть оба прогона и проверка ответа API после запуска через Docker Compose.
